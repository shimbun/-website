## 1. SEOキーワード戦略

### 1-1. 基本方針
1. **「悩みを解決する記事」を先に作り、KWは後から当てる**。SEO目的だけの量産はしない（月2〜4本、品質優先）。
2. YMYL（子どもの進路・教育）を意識し、全記事に**執筆者・監修者・更新日・根拠**を明記。
3. ビッグKWは「サービスページ／TOP」で中長期的に狙い、短期は悩み系ロングテールで流入を作る。
4. 地域が確定したら「中学受験 相談 東京」等のローカルKWを追加（§11で確認）。

## 2. サイト全体のURL設計・ページとキーワードのマッピング

### 2-1. URL設計ルール
- 英小文字・ハイフン区切り・末尾スラッシュ統一（`/about/`）。日本語URLは使わない。
- 階層は最大3階層。コラム記事は**カテゴリを URL に含めない**フラット構造（`/column/{slug}/`）とし、カテゴリ変更時の URL 変更リスクを避ける。カテゴリ一覧は `/column/category/{slug}/`。
- パラメータ付き URL（絞り込み、UTM 等）は canonical で正規 URL に統一。
- サンクスページ・検索結果ページは `noindex`。

## 7. 内部リンク設計（ハブ&スポーク）

### 7-1. 全体構造
```
            [コラム記事（スポーク）]
                  │ 本文中の文脈リンク／記事末ボックス
                  ▼
     [カテゴリのピラー記事] ◀──▶ [同カテゴリの記事同士]
                  │
                  ▼
        [サービス詳細ページ（ハブ）] ◀── 支援事例／お客様の声／FAQ
                  │
                  ▼
           [料金] → [相談予約（ゴール）]
```

### 7-2. ルール
1. **コラム記事 → サービス**：各記事は対応サービス1つを「主リンク」として本文中（文脈内）＋記事末ボックスで明示。カテゴリ⇔サービスの対応は§5の表どおり。
2. **コラム記事 → 相談予約**：記事末に CTA を1か所（＋長文記事はH2中盤に控えめなテキスト CTA 1か所）。追従バナーはスマホで本文を妨げない最小サイズに。
3. **コラム記事同士**：同カテゴリのピラー記事へ必ずリンク。関連記事3本は手動選定（自動表示だけに頼らない）。
4. **サービス → コラム**：各サービスページ下部に「このテーマのコラム」3本（ピラー＋人気記事）。サービスページの専門性補強。
5. **サービス → 事例・声・FAQ**：該当テーマで絞った事例1〜2件、FAQ 3〜5問を掲載。
6. **サービス → 料金 → 相談予約**：全サービスページに料金アンカーと CTA。
7. **コンサルタント ⇔ 記事**：執筆者プロフィールページから担当記事一覧へ、記事から執筆者ページへ（E-E-A-T）。
8. **パンくず**：全ページに設置（TOP > コラム > カテゴリ > 記事 / TOP > サービス > 各サービス）。
9. **アンカーテキスト**：「こちら」ではなく内容を示す語（例：「塾選び・転塾相談の詳細」）。
10. **グローバルナビ**：COMPASSとは／サービス／料金／コンサルタント／事例／コラム／FAQ ＋ 右端に CTA ボタン。フッターに全サービス・法務ページ。
11. **計測**：相談予約リンクには `?from=` 等の流入元パラメータまたは GA4 イベントで記事別 CV を計測。予約ページは canonical で正規化。

## 8. 構造化データ方針（JSON-LD）

実装形式は JSON-LD。**画面に表示している内容のみ**をマークアップ（非表示情報・架空の評価は入れない）。

| スキーマ | 付与ページ | 主なプロパティ | 注意点 |
|---|---|---|---|
| Organization | 全ページ共通（または TOP・/company/） | name, url, logo, description, contactPoint, sameAs（公式SNSがあれば） | 運営法人名・所在地は§11で確認 |
| ProfessionalService（LocalBusiness 系） | TOP または /company/ | name, address, telephone, areaServed, openingHours, priceRange | **実店舗・面談所がある場合のみ** LocalBusiness 系を使用。オンライン専業なら Organization＋Service に留め、住所は特商法表記に合わせる |
| Service | 各 `/service/*/` | serviceType, provider（Organization 参照）, areaServed, offers（price, priceCurrency=JPY） | 料金はページ表示と一致させる |
| FAQPage | `/faq/`（＋記事内FAQ） | mainEntity（Question/acceptedAnswer） | Google の FAQ リッチリザルトは現在、政府・医療等の権威サイト以外には原則表示されないため、**リッチリザルトは期待せず、内容理解・AI検索向けの補助として実装** |
| Article（BlogPosting） | `/column/{slug}/` | headline, datePublished, dateModified, author（Person 参照）, reviewedBy相当（監修者は本文表示＋author/Person 情報で表現）, image, publisher | dateModified は実際の内容更新時のみ変更 |
| BreadcrumbList | TOP 以外の全ページ | itemListElement | 画面のパンくずと一致 |
| Person | `/consultants/{slug}/`、記事の author | name, jobTitle, description, image, knowsAbout, worksFor, sameAs | 経歴は**事実のみ**。資格・実績は確認済みのもの |
| WebSite | TOP | name, url | サイト内検索がなければ SearchAction は付けない |

**使わないもの**：AggregateRating／Review（お客様の声への星評価マークアップは、自社掲載レビューの自己評価に当たりリッチリザルト対象外かつガイドライン違反リスクがあるため付与しない）。

## 9. テクニカルSEO要件

| 項目 | 要件 |
|---|---|
| sitemap.xml | 自動生成。index 対象ページのみ（noindex・thanks・404 除外）。lastmod は実更新日。Search Console に送信。記事が増えたら sitemap index で分割 |
| robots.txt | 全許可を基本に、`/consultation/thanks/`、管理画面、検索結果・パラメータ URL を Disallow（noindex との併用に注意：noindex させたいページは Disallow しない）。Sitemap 行を記載 |
| canonical | 全ページに自己参照 canonical。UTM・`from` パラメータ付きは正規 URL を指定。www/非www、http/https、末尾スラッシュを 301 で統一 |
| meta robots | thanks・タグ一覧（初期）・記事数の少ないカテゴリ・ステージング環境は noindex。**ステージングは Basic 認証＋noindex** |
| OGP / X Card | 全ページ og:title / og:description / og:image(1200×630) / og:url / og:type（TOP=website、記事=article）。記事は個別OGP画像（タイトル入りテンプレート）。twitter:card=summary_large_image |
| 見出し構造 | 1ページ1 H1、階層を飛ばさない |
| Core Web Vitals | 目標（モバイル・75パーセンタイル）：**LCP ≤ 2.5s、INP ≤ 200ms、CLS ≤ 0.1** |
| 表示速度施策 | 画像 WebP/AVIF＋width/height 指定＋遅延読み込み（FVの LCP 画像は preload・遅延させない）、Webフォントはサブセット化＋font-display: swap（日本語フォントは重いのでシステムフォント併用も検討）、JS 最小化・第三者タグ（GA4・予約ツール・チャット）は遅延読込、CDN・キャッシュ、静的生成（SSG）推奨 |
| モバイル | モバイルファースト。タップ領域 48px 以上、横スクロールなし、フォーム入力最適化（inputmode、autocomplete） |
| HTTPS | 全ページ HTTPS、HSTS |
| 404 | 正しく 404 ステータスを返す。TOP・相談予約・コラムへの導線を置く |
| リダイレクト | 旧サイトがある場合は旧 URL→新 URL の 301 マップを作成（§11で確認） |
| 計測 | GA4（相談予約完了＝キーイベント、CTA クリック、記事別 CV）、Search Console（ドメインプロパティ）、必要に応じ Microsoft Clarity 等は同意取得を前提に |
| アクセシビリティ | alt テキスト、コントラスト、フォームラベル。SEO と信頼感の両面で必要 |
| 構造化データ検証 | リッチリザルトテスト／Schema Markup Validator で公開前チェック |
| 多言語 | 不要（日本語のみ）。`<html lang="ja">` |

## 10. 記事制作ガイドライン

### 10-1. E-E-A-T（YMYL配慮）
- **執筆者表示**：全記事に実名（または確認済みのビジネスネーム）、顔写真、肩書き、経歴、プロフィールページへのリンク。
- **監修者表示**：教育・進路判断に関わる記事は監修者を置き、「監修」欄に氏名・経歴を明示。監修の範囲（内容の正確性確認）も記載。
- **運営者情報・編集ポリシー**を公開し、記事フッターからリンク。
- **経験（Experience）**：相談現場で実際に多い悩み・判断の過程を、個人が特定できない形で盛り込む。

### 10-2. 一次情報・根拠
- 入試日程、募集人数、制度などの事実は**学校公式サイト・募集要項・自治体・模試会社の公開資料**を出典として明記。孫引き（まとめサイト・ブログ）を根拠にしない。
- 統計・数値は出典と調査年を明記。出典が確認できない数値は書かない。
- 事例は**実在の相談をもとに、保護者の同意を得て匿名化**。同意が取れない事例、創作の事例は掲載しない。創作の「例え話」を使う場合は「架空のケース」と明記。

### 10-3. 更新日表示・メンテナンス
- 公開日と最終更新日を併記。**実質的な内容更新時のみ更新日を変える**（日付だけの更新はしない）。
- 入試制度・日程に関わる記事は年1回（入試終了後〜夏）に見直し。見直し台帳（URL・担当・次回見直し日）を運用。
- 情報が古くなった記事は更新・統合・非公開を判断（低品質ページを放置しない）。

### 10-4. 表現ルール（誇大・煽り表現の禁止）
| 使わない | 言い換え例 |
|---|---|
| 絶対合格／必ず上がる／100%／確実 | 改善が期待できる／可能性を高める |
| 逆転合格保証／偏差値◯◯アップ保証 | （使用しない） |
| このままでは手遅れ／今すぐ転塾しないと失敗 | 早めに状況を整理しておくと、選択肢を広く検討できます |
| No.1／業界最高／圧倒的実績（根拠なし） | （根拠が示せる事実のみ記載） |
| ◯◯塾はダメ／◯◯塾では伸びない | 塾ごとに特徴があり、お子さまとの相性が大切です |
| 無料相談（無料でない場合） | 中学受験について相談する |

- 専門用語（例：「難関校」「併願パターン」「偏差値帯」）は初出で平易に説明。
- 景品表示法（優良誤認・有利誤認）、ステマ規制（2023年10月施行、広告であることの明示）に留意。お客様の声は**実在・同意取得済み**のもののみ、謝礼がある場合はその旨を表示。
- 子どもの個人情報・写真は掲載しない（使う場合は保護者の書面同意）。

### 10-5. 制作フロー
1. 企画（悩み・検索意図・KW・繋ぐサービスを1枚にまとめる）
2. 構成案レビュー（コンサルタント）
3. 執筆（一次情報・現場経験を必ず入れる）
4. 事実確認・監修
5. 表現チェック（本ガイドライン §10-4 のチェックリスト）
6. SEOチェック（title・description・見出し・内部リンク・alt・構造化データ）
7. 公開 → 3か月後に Search Console で検索クエリを確認し、リライト判断

### 10-6. 記事テンプレート（必須要素）
パンくず／H1／カテゴリ・タグ／執筆者・監修者／公開日・更新日／「この記事で分かること」／目次／本文／まとめ／関連サービスボックス／CTA／関連記事／出典／執筆者プロフィール

| 13 | 公式SNS・YouTube・note 等の有無 | sameAs、流入チャネル、記事の二次展開 |
| 14 | 特定塾名を記事に出してよいか（事実説明の範囲で） | 「塾選び」系記事の具体性 |
| 15 | 本書で新規提案した `/company/`（運営者情報）、`/editorial-policy/`（編集ポリシー）、`/flow/`（利用の流れ）ページの追加可否 | E-E-A-T、サイトマップ |
| 16 | 実測キーワードデータ取得ツール（Google 広告アカウント、有料SEOツール）の利用可否 | 推定ボリュームの検証 |
